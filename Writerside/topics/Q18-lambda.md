# Q18) 람다 표현식과 그 사용법

람다는 **값이 된 함수**입니다. 보통 함수는 이름을 붙여 선언하고 그 이름으로 부르지만, 람다는 이름 없이 코드 조각 자체를 하나의 값처럼 다룹니다. 값이니까 변수에 담고, 인수로 넘기고, 함수에서 돌려받을 수 있습니다.

```kotlin
val greet = { name: String -> "Hello, $name" }
println(greet("skydoves")) // Hello, skydoves
```

`{ name: String -> "Hello, $name" }` 이 통째로 하나의 값이고, `greet`라는 변수에 담긴 것뿐입니다. 이 값을 `map`이나 `filter`에 넘기면 그게 바로 Q15에서 본 고차 함수입니다. 람다는 그 고차 함수에 넘길 "행동"을 그 자리에서 바로 적는 방법입니다.

## 기본 문법 {#syntax}

람다는 항상 중괄호 `{}` 안에 씁니다. 파라미터가 있으면 `->` 앞에 나열하고, 뒤가 본문입니다.

```kotlin
{ 파라미터: 타입, ... -> 본문 }
```

- **본문의 마지막 식이 반환값**입니다. `return` 키워드를 쓰지 않습니다(쓰면 오히려 다른 의미가 됩니다 — 뒤 [람다 vs 익명 함수](#lambda-vs-anonymous)에서).
- 파라미터가 없으면 `->`도 생략합니다: `{ println("tick") }`.
- 타입은 문맥에서 추론되면 생략할 수 있습니다.

## it 축약과 그 한계 {#it}

파라미터가 **하나뿐이고 타입이 문맥에서 추론될 때**는, 파라미터 선언과 `->`를 통째로 생략하고 그 자리에 암시적 이름 `it`을 쓸 수 있습니다.

```kotlin
val numbers = listOf(1, 2, 3, 4, 5)
val doubled = numbers.map { it * 2 }   // it == 각 원소
println(doubled) // [2, 4, 6, 8, 10]
```

`map`의 시그니처가 `(Int) -> R`이라 컴파일러가 `it`의 타입이 `Int`임을 알기 때문에 선언이 필요 없습니다.

여기서 짚을 것 하나. `it`은 **타입을 추론할 수 있을 때만** 통합니다. 아무 문맥 없이 변수에 담으면 추론할 근거가 없어 오류입니다.

```kotlin
val square = { it * it }              // 오류: cannot infer a type for this parameter
val square = { x: Int -> x * x }      // OK: 파라미터를 명시
val square: (Int) -> Int = { it * it } // OK: 변수 타입으로 추론되어 it 사용 가능
```

즉 `it`은 "파라미터 이름을 `it`으로 짓는" 문법이 아니라 **이름을 아예 생략하는** 문법입니다. `{ it: Int -> ... }`처럼 `it`을 직접 선언하는 건 축약이 아니라 그냥 파라미터 이름을 `it`으로 지은 것이라, 축약의 취지와 어긋납니다.

또 하나, **람다가 중첩되면 `it`이 모호**해집니다. 안쪽 `it`이 바깥 `it`을 가리게 되므로, 이럴 때는 이름을 명시해야 합니다.

```kotlin
list.forEach { outer ->
    outer.items.forEach { inner ->   // it, it 로 두면 어느 쪽인지 불명확
        println("$outer - $inner")
    }
}
```

## 트레일링 람다 {#trailing-lambda}

함수의 **마지막 인자가 람다면 괄호 밖으로** 뺄 수 있습니다. 코틀린에서 `map { }`, `runCatching { }` 같은 코드가 언어 구문처럼 읽히는 이유입니다.

```kotlin
// 원래 형태
numbers.map({ it * 2 })

// 람다를 괄호 밖으로 (트레일링 람다)
numbers.map() { it * 2 }

// 람다가 유일한 인자면 괄호까지 생략
numbers.map { it * 2 }
```

인자가 여럿이면 앞의 것만 괄호에 남기고 람다만 밖으로 뺍니다.

```kotlin
numbers.fold(0) { acc, n -> acc + n }
```

## 람다의 실체 — FunctionN 객체 {#lambda-is-object}

람다가 "값"이라는 말에는 구현상의 무게가 있습니다. JVM에는 함수를 그대로 담을 타입이 없으므로, 람다는 컴파일되면 **`FunctionN` 인터페이스를 구현한 객체**가 됩니다. 파라미터가 하나면 `Function1`, 둘이면 `Function2`, 이런 식이고, 본문은 그 객체의 `invoke()`에 들어갑니다.

```kotlin
val greet = { name: String -> "Hello, $name" }
// 개념적으로 아래와 같다
val greet = object : Function1<String, String> {
    override fun invoke(name: String): String = "Hello, $name"
}
```

그래서 람다를 넘길 때마다 객체가 하나 만들어지고, 실행할 때 `invoke()`를 한 번 거칩니다. 바로 이 비용을 없애려고 나온 것이 Q16의 `inline`입니다. 람다가 객체라는 이 사실이 Q15(고차 함수의 비용) → Q16(inline) → Q18(람다)을 하나로 묶는 지점입니다.

## 변수 캡처 — 클로저 {#closure}

람다는 자기 안에서 선언되지 않은, **둘러싼 스코프의 변수에 접근**할 수 있습니다. 이렇게 바깥 변수를 붙들고 있는 람다를 클로저(closure)라고 합니다.

```kotlin
var counter = 0
val increment = { counter++ }   // 바깥의 counter를 캡처
increment()
increment()
println(counter) // 2
```

여기서 Java와 다른 점이 있습니다. **Java 람다는 `final`(사실상 불변)인 지역 변수만 캡처**할 수 있지만, **코틀린 람다는 `var`도 캡처해서 값을 바꿀 수 있습니다.** 위 예제의 `counter++`가 실제로 바깥 `counter`를 증가시키는 게 그 증거입니다.

내부적으로는, 캡처된 `var`를 컴파일러가 `Ref.IntRef` 같은 **참조 홀더 객체로 감싸서** 람다와 바깥이 같은 상자를 공유하게 만듭니다. 그래서 한쪽에서 바꾸면 다른 쪽에도 보입니다.

이 캡처에는 Q16과 이어지는 성능 함의가 있습니다. **아무것도 캡처하지 않는 람다**는 상태가 없어 인스턴스를 하나만 만들어 재사용(싱글턴)하지만, **뭔가를 캡처하는 람다**는 캡처한 값이 매번 다를 수 있어 호출마다 새 객체가 만들어집니다. 반복문 안이라면 이 차이가 쌓입니다.

## 람다 vs 익명 함수 {#lambda-vs-anonymous}

코틀린에는 이름 없는 함수를 만드는 방법이 하나 더 있습니다 — 익명 함수(anonymous function)입니다. 둘 다 "이름 없는 함수"지만 **`return`의 동작이 다릅니다.**

```kotlin
// 익명 함수: fun 키워드, 반환 타입 명시, return 사용
val square = fun(x: Int): Int { return x * x }
```

- **람다의 `return`**: 람다 안에서 그냥 `return`을 쓰면 람다가 아니라 바깥 함수를 끝내려는 시도가 됩니다(비지역 반환). 그래서 인라인 함수가 아니면 금지되고, 람다 자신만 빠져나오려면 `return@label`이 필요합니다. → Q16 [비지역 반환](Q16-inline.md#non-local-return)과 정확히 같은 이야기입니다.
- **익명 함수의 `return`**: 자기 자신(그 익명 함수)만 종료합니다. 바깥으로 새지 않습니다.

정리하면, 값의 마지막 식을 반환하는 짧은 코드에는 람다가 자연스럽고, 중간에 `return`으로 여러 번 빠져나오는 로직이나 반환 타입을 분명히 하고 싶을 때는 익명 함수가 맞습니다. 실무에서는 대부분 람다를 씁니다.

## 요약 {#summary}

> **TL;DR** — 람다는 값으로 다루는 익명 함수입니다. `{ 파라미터 -> 본문 }`으로 쓰고, 파라미터가 하나면 `it`으로 줄이며, 마지막 식이 반환값입니다. 실체는 `invoke()`를 가진 객체라 넘길 때마다 할당이 생기고(→ `inline`), 바깥 변수를 캡처하면 클로저가 됩니다.

1. **정체**: 이름 없이 값으로 다루는 함수. 변수에 담고, 넘기고, 돌려받을 수 있다.
2. **문법**: `{ 파라미터: 타입 -> 본문 }`. 마지막 식이 반환값이고 `return`은 쓰지 않는다.
3. **it**: 파라미터가 하나이고 타입이 추론될 때 이름을 생략하고 `it`을 쓴다. 중첩되면 이름을 명시한다.
4. **트레일링 람다**: 마지막 인자가 람다면 괄호 밖으로 뺀다. 유일한 인자면 괄호도 생략한다.
5. **실체는 객체**: `FunctionN`을 구현한 객체로 컴파일되고 본문은 `invoke()`에 담긴다. 이 비용이 `inline`의 이유(Q16).
6. **캡처/클로저**: 바깥 스코프 변수를 붙들 수 있다. 코틀린은 `var`도 캡처·수정 가능(Java와 차이). 캡처하면 호출마다 새 객체.
7. **vs 익명 함수**: `return`의 대상이 다르다. 람다의 `return`은 비지역 반환, 익명 함수의 `return`은 자기 자신.

<def title="Q) 람다는 내부적으로 어떻게 표현되나요?">

JVM에는 함수를 값으로 담는 타입이 없으므로, 람다는 컴파일되면 `FunctionN` 인터페이스(파라미터 개수에 따라 `Function0`, `Function1` …)를 구현한 객체가 되고 본문은 그 객체의 `invoke()`에 들어갑니다. 따라서 람다를 넘길 때마다 객체가 할당되고 실행 시 `invoke()`를 한 번 거칩니다. 이 비용을 호출 지점에서 없애는 것이 `inline` 키워드입니다(Q16).

<def title="Q) 코틀린의 변수 캡처는 Java와 어떻게 다른가요?">

Java 람다는 `final`이거나 사실상 불변인 지역 변수만 캡처할 수 있어 캡처한 값을 바꿀 수 없습니다. 코틀린 람다는 `var`도 캡처해서 값을 수정할 수 있습니다. 내부적으로는 캡처된 `var`를 `Ref.IntRef` 같은 참조 홀더 객체로 감싸 람다와 바깥이 같은 저장소를 공유하게 만들기 때문입니다. 참고로, 아무것도 캡처하지 않는 람다는 상태가 없어 인스턴스를 재사용하지만, 무언가를 캡처하는 람다는 호출마다 새 객체가 만들어집니다.

</def>
<def title="Q) 람다와 익명 함수의 차이는 무엇인가요?">

둘 다 이름 없는 함수지만 `return`의 동작이 다릅니다. 람다 안에서 쓴 `return`은 람다가 아니라 바깥 함수를 끝내려는 비지역 반환이라, 인라인 함수가 아니면 금지되고 람다 자신만 빠져나오려면 `return@label`이 필요합니다. 반면 익명 함수(`fun(x: Int): Int { ... }`)의 `return`은 그 익명 함수 자신만 종료합니다. 또 익명 함수는 반환 타입을 명시할 수 있습니다. 짧은 표현에는 람다를, 중간 반환이 많거나 타입을 분명히 하고 싶을 때는 익명 함수를 쓰지만 실무에서는 대부분 람다를 씁니다.
